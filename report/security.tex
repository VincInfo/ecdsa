\section{Security Risks}
The Elliptic Curve Digital Signature Algorithm (ECDSA) is a clever way of keeping our digital world secure. But, if we want to use ECDSA effectively, we need to pay attention to some of the challenges it brings, especially when it comes to how difficult it can be to implement because it's quite complex.

ECDSA's strength comes from the complicated math it is based on, and it uses smaller but tough-to-crack keys. This helps to save on data space. However, this complexity can also make ECDSA tough to put into practice. If not implemented correctly, it can easily lead to security issues.

In the following sections, we're going to explore two major challenges. We are going to explain the the potential pitfalls with bad random number generators, and the possibility of time-based attacks. We'll also provide possible solutions to mitigate these issues. Furthermore, we will present real-world examples of where such attacks have been successfully executed, providing a practical understanding of these concepts.

\subsection{Poor Random Number Generator}
The nonce, or a "Number used ONCE," is a crucial component of ECDSA and contributes a significant layer of security\footnote{Starting out, ChatGPT was overly concerned with predictability of generated keys. This is still important, but it is not a unique problem of random number generators to ECDSA. We had to clarify the issues with bad nonces.}. It must be unique and random for every signature to ensure the private key isn't revealed. However, the security of these nonces and, therefore, the overall encryption system heavily depends on the strength of the random number generator used. There are four key issues we need to consider while discussing the quality of random number generators for nonces: repetition, predictability, size and bias.

\subsubsection{Repetition}
\label{subsubsection:repetition}
Reusing a nonce in multiple signatures is a significant security flaw. Even though the messages signed might be different, the fact that the same nonce was used provides an attacker with a critical amount of information. With two signatures sharing the same nonce but different messages, the private key can be calculated.

To understand this, consider the ECDSA signature equation\footnote{Surprisingly ChatGPT generated these mathematical equations correctly. Only the formating had to be adjusted to get nice looking equations.}:

\begin{equation} \label{eq:1}
s = \frac{h(m) + r d}{k} \bmod q
\end{equation}

In this equation, \textit{k} represents the nonce, \textit{h(m)} is the hash of the message, \textit{d} is the private key, \textit{r} is the x-coordinate of the EC point \(r=kG\), and \textit{q} is the order of the elliptic curve's generator point \textit{G}. If the same nonce \textit{k} is used for two messages, \textit{m1} and \textit{m2}, resulting in two signatures \textit{(r, s1)} and \textit{(r, s2)}, notice that \textit{r}, the x-coordinate, is the same for both since the same \textit{k} was used.

This presents a problem as it allows any observer to calculate the nonce \textit{k} as:

\begin{equation} \label{eq:2}
k = \frac{h(m1) - h(m2)}{s1 - s2} \bmod q
\end{equation}

Once the nonce is known, the observer could afterwards calculate the private key \textit{d} using the private key equation:

\begin{equation} \label{eq:3}
d = \frac{s k - h(m)}{r} \bmod q
\end{equation}

This means that the reusing of nonces can lead to the exposure of the private key. Hence, it's crucial to ensure that nonces are unique and not reused when generating ECDSA signatures to maintain a secure system. This includes the use of a proper random number generator, that cannot produce the same number twice.

\subsubsection{Predictability}
If an attacker can predict the next number generated from a specific algorithm, it instantly voids the security of the cryptographic operations relying on that algorithm. ECDSA, in particular, relies on the randomness of the nonces generated. Predictable nonces can enable an attacker to reverse-engineer and reveal the private key with equation \ref{eq:3} in section \ref{subsubsection:repetition}. This vulnerability drastically undermines the effectivity of the ECDSA security protocol.

In parallel, the same principle applies to the generation of keys. Keys should ideally be unique and unpredictable. However, if the pseudo-random number generator used for the key creation is compromised, it results in a production of predictable keys, rendering the entire security protocol ineffective. An attacker could potentially predict future keys and gain unauthorized access to sensitive data. However this concept is not unique to ECDSA and is not further explored in this paper.

\subsubsection{Size}
When nonce values are of small sizes such as 64-bit or 128-bit, they are susceptible to cryptanalytic attacks. One possible attack is using Pollard's rho algorithm to solve for these small nonces. The algorithm can determine the discrete logarithm—that is, find the nonce—in a number of steps proportional to the square root of the size of the group. 64-bit or 128-bit nonces are small enough for a targeted attack to be feasible \cite{cryptoeprint:2019/023}.
